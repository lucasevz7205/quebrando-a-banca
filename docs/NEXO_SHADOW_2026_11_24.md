# NEXO — Shadow adapter (offline)
The existing study-shell.html registrar() builds respostas/<qid> and rodadas/<id> on the client. The server bridge in study-account.js scopes accounts, but accepts a generic value; study-documents.js enforces idempotency on aprendizagem events, not independent grading of each answer. Historical respostas.hist retains up to eight records, and does not version the answer key. The admin legacy path in estudar.jsx uses ClaudeDocument storage separately. Consequently an authenticated persisted record is not proof of independent assessment.

Decision: no automatic historical mastery import; no live data read or persistence; no UI connection. The adapter uses a curator-approved, versioned question + map snapshot and exact stable ID binding; unknown historical versions and ambiguous remissions are excluded, not guessed. Recognized answers are regraded, never treated as free recall. No inference of confusion from C/E alone. Correct guesses and blank attempts excluded. Suggestions are provisional diagnostic-only. Existing SRS remains unchanged. A future server ingestion path must authenticate ownership, version question and map at attempt time, grade from approved snapshots, enforce event IDs and transaction/idempotency, and distinguish AI suggestions and self-assessment from verified evidence. Preview disabled. The catalog in tests is synthetic and is not approved study content.

Next: build curated pilot manifests; design versioned server-side attempt ingestion, then a read-only preview using synthetic data. Do not attach to the current generic write bridge or write real SRS until approved. Existing baseline lint failures and missing AscensaoPrimitives.jsx test remain outside scope.
